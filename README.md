# 工具调用提示中枢 (nekro_tool_prompt_hub)

> NekroAgent 插件 · 把**「何时用工具、怎么用工具」**的提示词从人格预设里剥离出来，
> 以**系统级规范按回合注入**——人格回归纯粹的角色塑造，工具用法的迭代收敛到一处配置。

版本 **1.1.0**　作者 **NTidal**　许可 **MIT**

---

## 一、解决什么问题

实践发现：NA 里 LLM 是否主动调用插件工具，很大程度上取决于**人格预设（preset）里写没写**
「遇到 XX 就调用 XX 工具」这类指引。于是：

- 每加一个工具、每改一次用法，都要去翻人格文案；
- 换一个人格，整套工具指引得再抄一遍；
- 人格文件越来越臃肿，「角色塑造」和「工具用法」两种关注点耦合在一起。

本插件把后者抽出来单独管理：**不碰人格、不改其他插件**，通过
`mount_prompt_inject_method` 在**每个回合**往上下文里注入一块「工具调用规范」。

---

## 二、两种能力

### 1. 规范注入（每回合，被动）

| 组成 | 说明 |
|---|---|
| **注入导语** `PREAMBLE` | 向模型说明这套规范的定位：判断权在它、模糊意图也要主动评估、规范与人格不冲突、工具结果要用人格口吻转述 |
| **全局准则** `GLOBAL_RULES` | 跨工具的通用行动规范，每回合都注入（留空则跳过这一节） |
| **场景规则** `RULES` | 每条对应一类工具/场景；**可配触发关键词**，只在最近若干条消息命中时才注入，控制 token 开销；关键词留空则该条每回合注入 |

> 只注入「事实与规范」，不注入角色扮演要求——表达永远留给该角色的人格。

### 2. 工具搜索（按需，主动）

规范写得再全，也覆盖不了「模型临时想确认某个能力是否存在」的场景。本插件提供
**AGENT 沙盒方法 `search_plugin_tools(keyword)`**：按关键词搜索**全部已启用插件**的沙盒方法
（匹配方法名 / 显示名 / 描述 / docstring / 插件名），结果回灌后模型继续对话。

同一份能力也对人类开放：插件路由下的**只读搜索页**与 JSON 接口。

---

## 三、工作原理

NA 每个 agent 回合的 system prompt 由几部分拼成：

```
policy_kernel + persona(preset.content) + runtime_contract + 各插件能力块
                                                    └─ 由「沙盒方法函数名 + docstring」渲染
```

此外，启用了 `mount_prompt_inject_method` 的**常驻/激活**插件，其返回文本会被框架包成
`<plugin_runtime_context module_name="...">…` 注入**历史消息头部**，而 runtime_contract 里
已经向模型声明了这类内容是「权威的系统级上下文信息」。

本插件就是走这条通道：

- **常驻是硬要求**：prompt 注入只对 `always_awake` / 激活态的插件渲染，所以插件声明
  `allow_sleep=False`；
- **注入函数全量兜底异常**：`render_inject_prompt` 不捕获异常，一旦抛错会让整个 agent 回合
  的上下文组装失败——所以任何意外都降级为「本回合不注入」；
- **注入量受 `MAX_INJECT_CHARS` 保护**，超限按「导语 → 全局准则 → 规则顺序」截断并记日志。

## 四、安装

1. 把本目录放到 NekroAgent 插件工作目录：

   ```text
   {NEKRO_DATA_DIR}/plugins/workdir/nekro_tool_prompt_hub/__init__.py
   ```

   （数据目录是 bind mount，容器重建不会丢；也可在 NA WebUI 上传打包好的 zip）

2. **完全重启 NekroAgent**（prompt 注入钩子在启动时挂载）；
3. 在 WebUI 插件详情页确认已加载，日志会打印一行自检：

   ```text
   [tool_prompt_hub] 已加载 | enabled=True | 全局准则 0 字符 | 规则：每回合 0 条 / 关键词 1 条 | 上限 4000 字符 | 搜索结果上限 20
   ```

4. 到配置页写规则（**保存即写入内存配置，下一回合生效，无需重启**）。

## 五、配置项

| 配置项 | 默认 | 说明 |
|---|---|---|
| `ENABLE_INJECT` | `true` | 总开关；关闭后本插件不注入任何内容（**搜索仍可用**）|
| `PREAMBLE` | 见上文 | 注入导语，放在规范块开头说明这套规范的定位 |
| `GLOBAL_RULES` | 空 | 全局准则，每回合注入；留空跳过该节 |
| `RULES` | 一条停用的示例 | 场景规则列表，见下 |
| `KEYWORD_SCAN_COUNT` | `10` | 关键词规则匹配时回看最近多少条消息（含触发本回合的那条）|
| `SEARCH_MAX_RESULTS` | `20` | `search_plugin_tools` 单次返回上限（1–100），超出会提示模型换更具体的关键词 |
| `MAX_INJECT_CHARS` | `4000` | 注入总字符上限（500–20000），超出按顺序截断 |
| `EXCLUDE_CHAT_KEYS` | 空 | 这些频道的 `chat_key` 不注入任何规范 |
| `LOG_INJECT` | `true` | 每次注入写一条 INFO 日志（规则条数/字符数），确认生效后可关闭 |

**单条规则（`RULES` 的元素）**

| 字段 | 说明 |
|---|---|
| `name` | 规则名，同时作为注入分节的标题 |
| `content` | 注入正文，写「什么场景用、怎么用、注意什么」 |
| `keywords` | 触发关键词；**留空 = 每回合注入**，填写 = 仅在最近消息命中时才注入 |
| `enabled` | 关闭后该规则不参与注入 |

## 六、规则怎么写

**场景规则**（配关键词，平时不占上下文）：

```text
name: 天气
keywords: ["天气", "下雨", "气温", "带伞"]
content: 当用户询问天气、出行是否需要带伞等与天气相关的话题时，
         调用天气查询工具获取真实数据，基于返回结果回答；
         拿不到数据时如实说明，不要凭感觉编造天气。
```

**全局准则**（每回合都在，适合放"行动总纲"）：

```text
name: 行动总纲
keywords: []
content: 涉及可查证的事实（群里说过什么、之前记过什么、有什么工具可用）时，
         先查再答，不要凭印象编；查不到就如实说不知道。
```

> 写法要点：写**事实与行动规范**，别写"你要扮演一个活泼的助手"这类角色要求——
> 后者属于人格预设，混进规范会让人格表达变僵。

## 七、搜索页

挂在插件路由下（本机插件惯例无鉴权，**只读**）：

| 路径 | 说明 |
|---|---|
| `GET /plugins/NTidal.nekro_tool_prompt_hub` | 网页搜索页（输入关键词即时过滤，展示方法 / 插件 / 说明）|
| `GET /plugins/NTidal.nekro_tool_prompt_hub/api/tools?keyword=&limit=` | JSON；`limit=0` 用配置默认值，上限 100 |

结果里会标注：

- `AGENT` 标签——该方法是 AGENT 类型，调用后**必须先停止生成代码**再等结果回灌；
- `休眠` 标签——所属插件当前对本会话处于休眠态，其工具块在 prompt 里只有摘要，
  需先 `activate_plugin` 唤醒才会完整可见。

## 八、LLM 工具

| 工具 | 类型 | 说明 |
|---|---|---|
| `search_plugin_tools(keyword="")` | **AGENT** | 按关键词搜索已启用插件的全部沙盒方法；留空返回工具总量概览 |

搜索遵守适配器过滤（`support_adapter`）：当前平台用不了的工具不会出现。
返回值复用 system prompt 里已有的 `**[AGENT METHOD - STOP AFTER CALL]**` 标记，模型无需学习新约定。

## 九、常见问题

**改了配置但没生效**
配置保存后**下一回合**生效（注入发生在每回合组装上下文时），不需要重启。
若整块都没出现，先看 `ENABLE_INJECT` 是否为 true、该频道是否在 `EXCLUDE_CHAT_KEYS` 里。

**规则没被注入**
带关键词的规则只在最近 `KEYWORD_SCAN_COUNT` 条消息命中时才注入；
临时想验证可以先把关键词清空（变成每回合注入），或看日志里那行「已注入工具调用规范」。

**日志里没看到注入记录**
`LOG_INJECT` 关闭了，或者只有导语、没有任何实际规则（这种情况本插件会直接跳过以省 token）。

**"注入会不会和人格冲突"**
规范块被框架包在 `plugin_runtime_context` 标签里，且 runtime_contract 声明其为系统级权威上下文，
优先级高于人格；但本插件只约束**行动**（用不用工具、怎么用），不约束**表达**（怎么说话）。

**内容太长被截断**
调大 `MAX_INJECT_CHARS`，或者给规则加关键词让它按需注入——后者更省上下文。

## 十、设计要点

- **关注点分离**：人格管表达，规范管行动，各改各的；
- **省 token**：带关键词的规则按需注入，且导语之外没有任何规则时整块跳过；
- **绝不打断主流程**：注入函数与搜索函数都全量兜底异常，最坏情况是"这回合没注入/搜索返回空"，
  而不是 agent 回合失败；
- **不重复教约定**：搜索结果沿用框架已有的 AGENT 标记与休眠语义，不引入新的模型学习成本。
